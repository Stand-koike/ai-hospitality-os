## 2. Initial Customer Hypothesis

[06 §5](./06_BUSINESS_MODEL.md)、[02 §3](./02_PRODUCT_DEFINITION.md) と整合。

- **小規模宿泊施設**（パイロット：**個人経営・約 7 室・1 施設**）

## 4. Sales Entry Hypothesis

「Hospitality OS です」と **機能一覧から入るだけ**ではなく、施設が感じている **課題から入る**ことを仮説とする（課題の断定ではなく **初期の課題仮説**）。

| # | 課題仮説 |
|---|----------|
| 1 | 常連のことを一部スタッフだけが覚えて、**他スタッフに伝わらない** |
| 2 | お客様についての **気づきが残らない** |
| 3 | **申し送りが口頭中心**になる |
| 4 | 過去の宿泊情報を **探すのに時間がかかる** |
| 5 | 担当者によって **接客の理解度に差**が出る |
| 6 | 情報はあるが **必要なタイミングで見られない** |

入口はパイロットで **どの課題に反応するか**を検証する（§11）。

プロダクトの入口体験（[03](./03_MVP_SPEC.md)）：Today's Brief、Guest Resolution、記録のループと **接続**して説明する。

## 5. Value Communication

### 5.1 基本の方向（仮説）

**「情報を管理するシステム」** ではなく、

> **お客様を知り、気づきを残し、次のスタッフにつなげるための仕組み**

[01](./01_BRAND_BOOK.md)・[05](./05_UI_UX.md) の Guest-centered・行動変容と一致。

### 5.2 価値連鎖（06 と整合）

```text
Software
   ↓ 使われる
   ↓ 行動が変わる
   ↓ 情報が残る・共有される
   ↓ お客様への理解が深まる
```

**中心にしない訴求**（MVP 思想と矛盾）：「AI が接客してくれる」「AI が最適な接客を指示する」。

**使う言葉の例**（確定コピーではない）：Today's Brief、Guest Resolution、Timeline への短い記録、Guest 履歴の要約（補助）。

### 5.3 二層の伝え方

| 層 | 伝えること |
|----|------------|
| Software | 現場で **使われ、行動が変わる**再現可能なプロダクト |
| Hospitality Success | **伴走**で導入・定着を支える（無制限コンサルではない） |

Software だけを売って終わりにしない（[06](./06_BUSINESS_MODEL.md)）。

## 6. Initial Sales Model

**仮説：Founder-led / accompanied pilot**

初期段階では創業者が関与する想定（**長期的な販売モデルそのものではない**）。

| 関与 | 内容 |
|------|------|
| 説明 | 施設への藍 ai の考え方・MVP |
| 導入 | 初期設定・データの流れ（経路 **未決定**） |
| 現場 | スタッフへの使い方 |
| 確認 | 利用状況・行動変容の観察 |
| 学習 | フィードバック収集 → プロダクト・プレイブックへ |

**位置づけ**：販売・導入 **方法を学習する初期フェーズ**。のち §9 の再現可能化へ。

## 7. Pilot Acquisition

**7 室程度のモデル施設**（1 件 — 名称・地域 **未決定**）への導入フロー（仮説）。

```text
1. 施設との接点
2. 現場の課題・運用を確認
3. 藍 ai の考え方と MVP を説明
4. パイロット条件を設定（価格・期間は 07 未決定）
5. Software + 必要な伴走で導入
6. 実際の利用を観察
7. 行動変容・定着・価値を確認
8. フィードバックをプロダクトへ反映
```

営業チャネル・件数・成約率：**未決定**。

## 8. Pilot Success → Sales Asset

パイロットで残すもの（**架空の成功事例は作らない**）。

| 記録したいこと | 将来の活用（仮説） |
|----------------|-------------------|
| どの **行動**が変わったか | 導入事例・営業トーク |
| どの **機能**が使われたか | デモ・オンボーディング |
| どこで **利用が止まったか** | プロダクト改善 |
| **伴走**がどの程度必要だったか | Hospitality Success プレイブック |
| 経営者が感じた **価値** | Buyer 向け資料 |
| 現場スタッフが感じた **価値** | User 向け手順 |

単なる「導入実績」ではなく、**再現可能な販売・導入**の素材にする（§9）。

---

## 9. Sales Scalability Hypothesis

初期は創業者主導でもよいが、長期の目指す形（**仮説**）。

```text
Founder experience
   ↓
Pilot learning
   ↓
Product
   ↓
Onboarding Playbook
   ↓
Hospitality Success Playbook
   ↓
再現可能な販売・導入
```

**長期的な前提にしない**

- 「創業者が話さないと売れない」
- 「創業者が付き添わないと使えない」

[06 §7](./06_BUSINESS_MODEL.md)、[02](./02_PRODUCT_DEFINITION.md) と一致。
